## 1. Before you build

1. **Update your privacy policy and terms** at <https://chamowil.github.io/act-prep-support/>. They were written
   for an ACT-only iOS app. They should now mention the SAT, that the app also runs on Android, that all study data
   stays on the device, and that purchases are handled by Apple/Google. Both stores require a working privacy URL.
2. **Have a person review the SAT content.** The 426 SAT questions are original, but they were produced for this
   project: the 303 Math items are generated by `tools/gen_sat_math.py` with computed answers; the 123 Reading &
   Writing items were hand-written. A qualified tutor should read them before release, because wrong answer keys
   are the biggest risk for a test-prep app. Scores are approximations; the app says so and never claims to be official.
3. **Trademarks.** "ACT" and "SAT" are trademarks of ACT, Inc. and the College Board. Keep the "not affiliated"
   disclaimer in the app (Settings), the description, and the website, and never use their logos. A rejection under
   Apple 5.2.1 or a Play "impersonation / intellectual property" flag is possible when a name contains a test name;
   if it happens, use a name such as "Test Prep: Practice for ACT & SAT" and keep the disclaimer.

## 2. Build the release artifacts

```bash
flutter pub get
flutter test                       # 64 tests, must pass
flutter build appbundle --release  # -> build/app/outputs/bundle/release/app-release.aab
flutter build ipa --release        # -> archive in build/ios/archive/Runner.xcarchive
```

### Android signing

An **upload keystore** was generated at `android/app/upload-keystore.jks` with its passwords in
`android/key.properties`. Both are git-ignored. **Back them up now** (password manager plus an offline copy).
With Play App Signing (default and recommended) a lost upload key can be reset by Google support, but it is a delay.

Certificate fingerprint of the upload key (SHA-256):
`7A:FF:26:9D:A3:B4:40:19:31:A1:E6:2E:90:07:7F:55:04:7C:C1:8A:DB:9C:FE:34:DE:62:D1:D3:C8:8B:2B:D3`

To create your own key instead:

```bash
keytool -genkeypair -v -keystore android/app/upload-keystore.jks -storetype JKS \
  -keyalg RSA -keysize 2048 -validity 10000 -alias upload
```

then put `storePassword`, `keyPassword`, `keyAlias=upload`, `storeFile=app/upload-keystore.jks` in `android/key.properties`.

### iOS signing

`flutter build ipa` produces a signed **archive**, but the export step stops with *"No Accounts / No signing certificate
iOS Distribution"*, because Xcode on this Mac has no Apple ID signed in. Fix once:

1. Xcode → Settings → **Accounts** → add the Apple ID that belongs to team `WYS4LUJSP6`.
2. Run `flutter build ipa --release` again; Xcode creates the Distribution certificate and profile automatically.
   The IPA appears in `build/ios/ipa/`.
3. Upload with Xcode (Window → Organizer → archive → **Distribute App → App Store Connect → Upload**) or with the
   free **Transporter** app.

## 3. Google Play Console

### 3.1 Account and app
1. Developer account (one-time $25). Personal accounts created after Nov 2023 must run a **closed test with at least
   12 testers for 14 days** before applying for production access. Check the current rule in Play Console → Dashboard.
2. Set up a **payments profile / merchant account** (Settings → Payments profile). Required to sell subscriptions.
3. **Create app**: name `ACT & SAT Prep`, default language English (US), App, **Free**, accept the declarations.

### 3.2 Upload the first build
Testing → **Internal testing** → Create release → upload `app-release.aab`. Accept **Play App Signing** when asked.
Billing products can only be created after a build containing the billing permission has been uploaded.

### 3.3 Create the subscriptions
Monetize with Play → **Products → Subscriptions → Create subscription**.

| Subscription ID | Base plan ID | Billing | Price |
|---|---|---|---|
| `actprep.pro.monthly` | `monthly` | Monthly, auto-renewing | $19.99 |
| `actprep.pro.yearly` | `yearly` | Yearly, auto-renewing | $99.99 |

For the yearly subscription add an **offer** on the `yearly` base plan: eligibility *New customer acquisition*, phase
*Free trial*, **7 days**. The app reads the trial from Play and shows it only to eligible users.
Activate both base plans. The IDs must match `lib/config.dart` exactly.

### 3.4 Store listing and policy forms
Grow → Store presence → **Main store listing**: paste text from `STORE_LISTING.md`; upload
`publish/android/graphics/icon-512.png`, `publish/android/graphics/feature-graphic-1024x500.png`, and at least 2 phone
screenshots (see §5).

Policy → **App content**:

| Form | Answer |
|---|---|
| Privacy policy | `https://chamowil.github.io/act-prep-support/privacy.html` |
| Ads | No ads |
| App access | All functionality available without login |
| Target audience | **13+** (choose 13–15, 16–17, 18+; do **not** select under-13, which triggers the Families policy) |
| Content rating (IARC) | Category *Reference, news or educational*; answer **No** to every violence/sex/language/gambling/user-content question. Expect "Everyone". |
| Data safety | See below |
| Government / financial / health apps | None apply |

**Data safety**: *Does your app collect or share any of the required user data types?* **No.** All progress, scores and
essays stay on the device. Purchases are processed by Google Play and are not data you receive. Data is not encrypted
in transit because none is transmitted; answer the "deletion" question with "no data collected".

### 3.5 Test purchases, then release
1. Setup → **License testing**: add your Gmail address(es). Add the same people as testers on the Internal track and
   install via the opt-in link. Purchases by license testers are free and renew on a fast schedule.
2. Verify: both plans load with correct prices; the yearly plan shows the trial; purchase unlocks questions 11+,
   mock exams 2+, all tutorials; **Restore Purchases** works after reinstall; **Manage subscription** opens Play.
3. Promote to Closed testing (12 testers, 14 days if required) → Production → Roll out.

## 4. App Store Connect

1. **Register the bundle ID** `Wuilmer.Ponte.ACT-SAT-prep` at <https://developer.apple.com/account/resources/identifiers/list>
   (Xcode does this automatically on first signed build).
2. **Business → Agreements**: the *Paid Applications* agreement must be **Active**, with banking and tax complete.
   Without it, subscriptions silently fail to load.
3. **Apps → +/New App** (or open the existing record): iOS, name `ACT & SAT Prep` (30 characters max; if taken use
   `ACT & SAT Prep: Practice`), English (U.S.), bundle ID above, SKU e.g. `ACTSATPREP001`.
4. **Subscriptions**: group `ACT Prep Pro`; products `actprep.pro.monthly` (1 month, $19.99) and
   `actprep.pro.yearly` (1 year, $99.99) with an **Introductory offer: Free, 1 week, all countries**. Ranking:
   yearly above monthly. Add localizations (display name and description from `STORE_LISTING.md`) and a review
   screenshot of the paywall. First-time subscriptions must be attached to the version you submit.
5. **App Information**: category Education (secondary Reference), age rating questionnaire → all **None** (4+),
   privacy policy and support URLs.
6. **App Privacy**: *Data Not Collected*. This matches `ios/Runner/PrivacyInfo.xcprivacy` (no tracking, no collected data).
7. **Screenshots**: upload `publish/apple/screenshots/iphone-6.9/*` (1320×2868) and `publish/apple/screenshots/ipad-13/*` (2064×2752).
8. **Upload the build** (see §2). Export compliance is pre-answered (`ITSAppUsesNonExemptEncryption = NO`).
9. **TestFlight** first: add yourself as an internal tester, create a Sandbox Apple Account (Users and Access →
   Sandbox), and run the same purchase checklist as in §3.5.
10. **Submit for review** with the notes in `STORE_LISTING.md` and **both subscriptions added to the submission**.

## 6. After launch

- Price changes, promotional text, and listing text can change without a new build.
- New content is JSON in `assets/`; SAT Math questions can be regenerated with `python3 tools/gen_sat_math.py`.
  Run `flutter test` after any content change; it validates every question.
- **Subscription hardening:** entitlement is checked on-device through the store plugin and re-verified on each launch.
  Before you depend on subscription revenue at scale, consider server-side receipt validation (for example RevenueCat)
  to protect against tampered devices.
